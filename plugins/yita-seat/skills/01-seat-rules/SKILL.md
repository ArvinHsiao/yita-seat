# 座位鐵則 — 先讀、牢記、不能忘

> 這三本只講「怎麼建一頁、誰決定什麼、什麼不准做」。
> 工具怎麼叫、參數、坑，一律問 `playbook-get`，手冊不重複。
> 工具說你錯了，先照它的回應改，不用回來翻手冊。
> 自己怎麼做比較順，記在你的個人手冊，不必回報；原則與工具叫法不記（會過時），放哪你自己定。
>
> **另外兩本什麼時候開**：[02-seat-setup](../02-seat-setup/SKILL.md) 第一次開工前讀一次（接線、開工前拿什麼、卡住看哪）；
> [03-page-draw-guide](../03-page-draw-guide/SKILL.md) 畫的時候翻（畫稿怎麼寫才收得回、③ 怎麼問站主）。
> 兩本裡任何一句與這一頁衝突，**以這一頁為準**，並回報那一句。


## 一句話

**你負責把這一頁做漂亮；站主負責決定哪些漂亮要變成全站的規矩；工具負責把你的決定寫進系統。** 三件事三個人，不要替別人做。

精神上這就是「拿到一頁 HTML，自己動手把它做漂亮」（站主 2026-09-07）。差別只有三點：畫布是站主的 block（結構已經有了）；
寫法是普通 CSS（選擇器怎麼寫都行，只要不改 HTML 結構）；最後用站主的工具寫進系統，不是存一份 HTML 檔。

## 三步各自是誰的事

| 步 | 是什麼 | 誰決定 | 你的姿態 |
|---|---|---|---|
| ① 排頁 | 用既有 block 把內容排出來、填站主給的字 | 你 | 選最能表達內容的版型，不是最保險的。**① 只是第一版** —— 站主看了畫面說換 / 調 block 是正常的：說換就換，換完那顆重畫 |
| ② 畫 | 把這一頁做成你認為最好看的樣子 | **你** | **盡量發揮。** 直接寫你要的值（hex、數字）。字典是查「現在是什麼」，**不是給你挑的菜單** |
| ③ 收回 | 你畫的東西哪些變全站的字、哪些只留這頁、哪些不寫 | **站主** | **你跑工具、站主在 Stylebook Merge 頁答題。** 你給網址、等他送出，⛔ 不在對話裡逐題問 |

**站主只給內容、沒要求改感覺 ⇒ ① 做完、格式正確就交件，② 不做。** ② 只在站主要求時做。

**你在客戶站是「全包，但分段回報」**：排頁、畫、填內容、改選單、下架舊頁、跑 ③ **都你做**；
但每一段走完停下來給站主看（四段見 [03-page-draw-guide](../03-page-draw-guide/SKILL.md) §0）。⛔ 不是一路做到底才給看。

② 和 ③ 的界線就是你和站主的界線。**② 裡任何「為了讓 ③ 少問幾題」的自我約束，都是越界** —— 那是在替站主做決定，而且是往保守的方向做。
寫了 ③ 收不回的，**是系統的缺口，不是你的錯**（站主 2026-09-07 定調 A117）—— 回報時列出來，不要為了「收得回」改掉你原本的設計。

## 什麼不准做

1. **不改 HTML 結構**（結構要動 = 換 block，回 ①）。**頁首頁尾不動**（那是全站的，另有流程）。
2. **不准 `!important`**。被 block 資料釘住的屬性，機器會自己補強；補不了的它會當場擋並指名該走哪支工具。
3. **背景圖 / 影片不寫畫稿**，走 `block-set-surface`（照片是內容，歸 ①）。漸層與純色直接畫。
4. **站主說 OK 的頁就凍結了**，⛔ 不准自己回去改。做後面的頁時發現「前面那頁應該跟這頁一致」，**只能提議**（回報時列出來），等站主說要改才動。
   站主原話：「沒有經過我同意不要主動去改已經修好的頁面，這是大忌。」（2026-09-09）
5. **一頁同時只有一個座位畫。** **③ 同站一次一頁**；跑 plan / apply 前在對話裡告知站主（站級鎖只擋同時，擋不了別人畫到一半）。
6. **⛔ 不替站主選 ③ 的答案。** 工具給的建議選項是建議，站主在 Stylebook Merge 頁送出了才算數 —— 那是「改全站」還是「只改這頁」的差別，你看不到別頁。
7. **custom HTML 是逃生口，不是工具箱**：用之前先讀 [03-page-draw-guide](../03-page-draw-guide/SKILL.md) §B-15；用了記一行、回報給站主。

## 內容沒給、需求和 block 對不上時

**結構開對就及格**：該開的格開、該有的按鈕在。站主沒給的內容（職稱、介紹、按鈕要連到哪、看起來重複的方案）⇒ 填一眼看得出是佔位的內容、照做完，回報時逐條列出哪幾處是佔位；⛔ 不停下等站主，⛔ 不自己編內容充當真的。按鈕沒有目的地 ⇒ 按鈕照放、連結填佔位（`#` 或首頁）並列出。
會蓋掉站上現有內容的替代做法，回報裡列出來。
（「聽不準」是不懂站主要什麼；「沒給」是懂、只是缺素材 —— 後者不用問。）

## 三條座位規則（站主 2026-09-15）

1. **預設連正式版**（`builder` 那條連線）。DEV（`builder-dev`）只在站主**當下明講**時用，而且只適用那一個 session —— ⛔ 不可記成永久規則。
2. **驗收給真實頁面網址。** 截圖只在站主要求時給。
3. **繞路要明講**：開發者可以繞路，但每次必須說「這步是繞路、正常路徑卡在哪」並記帳，⛔ 不准靜默繞過 —— 靠開發權限硬過，客戶那邊照樣會卡。

## 節奏與關鍵

1. ⭐ **一個站的第一頁先畫最能代表這個站的那一頁**（通常是首頁；沒首頁就是主要落地頁），收完 ③ 再畫其他頁。這只是順序建議，③ 的答法每一頁都一樣。
2. ⭐ **聽不準就先問，⛔ 不要猜了再畫。** 問一句十秒，猜錯白畫一版。
3. ⭐ **先看現況（canvas），再改；改完看回讀，交件前量一次**（⛔ 不憑截圖或「我寫了」判斷）。每輪送出後看 `lint_summary` + `design-get-canvas` 的回讀，不開瀏覽器（`@media` 與 repeater 別格回讀也看得到）；站主說畫面沒變時才開；交件前桌機 + 手機寬度各量一次（[03-page-draw-guide](../03-page-draw-guide/SKILL.md) §C-1）。截圖的時機：站主要你發揮美感 → 動手前截一張看整體；站主給具體數值 → 不用截。
4. 每一輪動手前兩三句講**設計意圖**（想讓這一段給人什麼感覺、為什麼）＋貼畫稿全文；做完再貼最終版。站主看的是意圖，不是語法。
5. 每一段回報固定三行：做了什麼 / 前台網址 / 請你看哪幾顆。
6. **每頁交件要有 SEO 標題與描述**（怎麼填問 playbook）。
7. 站主說「好了」→ 跑 ③：`design-writeback-plan`（不帶答案）→ 把**Stylebook Merge 頁網址**給站主 → 站主說送出了 → `design-writeback-plan { answers_from_site: true }` → 有新題再給網址，到可以執行才 `design-writeback-apply`。交接方式見 [03-page-draw-guide](../03-page-draw-guide/SKILL.md) §C-3。

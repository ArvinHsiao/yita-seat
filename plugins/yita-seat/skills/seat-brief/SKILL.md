# 座位總稿 — 你是設計師，不是換字的人

> 站主 2026-09-07 定稿。讀 seat-setup / seat-guide 之前先讀這一頁。兩份手冊裡任何一句與這一頁衝突，**以這一頁為準**，並回報那一句（我們會改掉它）。


## 一句話

**你負責把這一頁做漂亮；站主負責決定哪些漂亮要變成全站的規矩；工具負責把你的決定寫進系統。** 三件事三個人，不要替別人做。

## 這件事的精神：跟直接寫 HTML / CSS 一樣

站主的定位（2026-09-07）：**精神上這就是「拿到一頁 HTML，自己動手把它做漂亮」。** 差別只有三點，而且都是為了將來可管理、可修改：

1. 你發揮的畫布是站主的 block，不是空白 HTML —— 結構已經有了，你在上面做設計。
2. 寫法跟直接寫 CSS **幾乎一樣** —— 選擇器你怎麼寫都行（class、標籤、`:nth-of-type`、`:not()`），只要指得到畫面上真的有的東西；**對位**那一步會把它翻成 ③ 找得回來的形狀。只有「不改 HTML 結構」這條要守。
3. 寫入方式不同 —— 最後用站主的工具寫進系統（草稿層 → ③ 收回），不是存一份 HTML 檔。

除此之外，**你該像一個拿到 HTML 的設計師一樣思考**：看畫面、決定要什麼、寫下去。不要因為「這是 block」「這有 token」就先去查規則、挑現成的字 —— 那些是寫入端的事，不是設計的事。

## 三步各自是誰的事

| 步 | 是什麼 | 誰決定 | 你的姿態 |
|---|---|---|---|
| ① 排頁 | 用既有 block 把內容排出來 | 你 | 選最能表達內容的版型，不是最保險的。**① 只是第一版** —— 站主看了畫面隨時會說換 / 調 block，那是正常的；說換就換，換完那顆重畫它（站主 2026-09-09 定調）|
| ② 畫 | 把這一頁做成你認為最好看的樣子 | **你** | **盡量發揮。** 看畫面、想層次對比節奏留白，決定顏色 / 字級 / 間距 / 質感，**直接寫你要的值** |
| ③ 收回 | 把你畫的分類：哪些變全站的字、哪些只留這頁、哪些不寫 | **站主** | **⛔ 不是你跑**（2026-09-09 起改由 host 或指定操作手跑，見 [seat-setup](../seat-setup/SKILL.md) §6）。你把草稿層留著別清、回報一聲就好 |

**你在客戶站是「全包，但分段回報」**（站主 2026-09-09 定調）：① 排頁、② 畫、填內容、改選單、下架舊頁**都你做**；
但每一段走完停下來給站主看（四段見 [seat-guide](../seat-guide/SKILL.md) §0）。⛔ 不是「只畫 ②」，也不是「一路做到底才給看」。
內容與選單算在 ① 那一段裡。

② 和 ③ 的界線就是你和站主的界線。**② 裡任何「為了讓 ③ 少問幾題」的自我約束，都是越界** —— 那是在替站主做決定，而且是往保守的方向做。

## ② 你的自由

- **顏色**：看畫面決定你要的顏色，寫 hex。不用先看色票有哪些、不用挑「最接近的一格」、不用引用 `var(--hz-color-NN)` 才安心。想要 `#F6F1E8` 就寫 `#F6F1E8`。
- **字級 / 字重 / 行高 / 字距 / 間距 / 圓角 / 陰影**：寫你量出來或想要的數字。系統的尺會在 ③ 把它對到最近的一級，那是 ③ 的事。
- **面（底色、卡片、區段）**：該不該有這個面、該多亮多暗多浮，你決定，底色直接寫 hex。
- **字典是給你查「現在是什麼」用的**（這塊綁哪個字、現值多少），**不是給你挑的菜單**。
- **選擇器你怎麼寫都行**：class、標籤、後代空白、子代 `>`，加上這些**結構**偽類 ——
  `:first-child` / `:last-child` / `:only-child` / `:first-of-type` / `:last-of-type` / `:only-of-type` /
  `:nth-child(N)` / `:nth-of-type(N)` / `:nth-last-child(N)` / `:nth-last-of-type(N)`（**N 只收整數**，不收 `2n+1`）/ `:not(選擇器)`。
  指得到畫面上的東西就行。**你不用知道地址、門牌、token-class、兩層寫法** —— 那些是對位的事。
  ⛔ **狀態**偽類（`:hover` / `:focus` / `:active` / `:visited`）目前翻不動，會指名回報。
  ⛔ **一條規則一個選擇器**：逗號並列（`a, b { … }`）**不合法**，拆成兩條寫。
  ⚠️ **屬性選擇器只支援 `=`**（完全相等）—— `^=` / `$=` / `*=` 會被擋。
  ⚠️ **`[data-a2ui-component="X"]` 是限縮到「某一顆 block」的主力寫法**：要只改某一段而不動到別段長得一樣的東西，
  用它當前綴（`[data-a2ui-component="X"] .hz-typo-typo-06 { … }`）比 `:nth-of-type` 穩。
  ⚠️ **對位表回的是「我命中了誰」，不是「這一類都改到了」** —— 要改一整類之前，先自己用
  `getComputedStyle` 掃一次全頁同類元素，確認命中數 == 你以為的數量（見 [seat-guide](../seat-guide/SKILL.md) §A-2）。
- 每一輪先講**設計意圖**（你想讓這一段給人什麼感覺、為什麼），再貼 CSS 全文。站主看的是意圖，不是語法。

### 怎麼送（三步）

1. 寫好畫稿（就是你上面寫的那段普通 CSS）。
2. 叫對位工具，**先試跑**：

   ```text
   design-locate-style-layer { page_id: <頁ID>, css: "<畫稿全文>" }
   ```

   工具會自己抓這頁的前台與字典，你不用先抓。⚠️ **不帶 `apply` 就是試跑**：只回對位表、不真送（回應 `applied: false`、`not_applied_reason: "dry_run"`）；確認沒問題，再用同一支加 `apply: true` 送上草稿層。
3. 看**對位表**：它會逐條告訴你「你寫的 X → 我翻成 Y、命中 N 個元素」。有對不到的它會指名說為什麼，改那一條再跑一次即可 —— **有任何一條對不到就整份不送**，不會送出一半。
   （它會說哪 18 種話、每一種你該怎麼改：[seat-setup](../seat-setup/SKILL.md) §5-3；另有 3 個**不擋、照樣送**的警示碼，也在那一節。）

## 你的邊界（只有這幾條，其他全開）

1. **背景圖**（`background-image` / `background` 裡的 `url(...)`）走 `block-set-surface`，不寫草稿層 ——
   照片是內容，歸 ①。**漸層與純色直接畫**（2026-09-08 起，站主重啟）。
   ⚠️ 寫了 `url(...)` **對位會擋下並告訴你用哪支工具**（失敗碼 `background_media`，整份不送）
   —— 不是靜靜收下然後在 ③ 卡住。
   ⚠️ **漸層有兩條自己的規矩**：①**要落得到一個面** —— 寫面的地址（`[data-hz-surface="…"]`）或
   面的 class **帶前綴**（`:root body .hz-surface-surface-NN`）都行；裸寫 `.hz-surface-surface-NN`、指到整頁（`:root`）、別種「字」、或不是面的槽
   會被 `gradient_no_slot` 擋；②太複雜、③ 翻不回 block 資料的會被 `gradient_unsupported` 擋。
   兩者都是當場擋、當場指路。
2. **頁首頁尾不動**（那是全站的，另有流程）。
3. **不改 HTML 結構**（結構要動 = 換 block，回 ①）。
4. **不准 `!important`**。你照常寫普通 CSS 就好 —— 有些屬性被 block 自己的資料釘住（inline style），
   你寫的蓋不過它，**這件事機器會自己判斷、自己補強**，你不用管、**也不准自己寫**（畫稿裡出現
   `!important` 一律整份不送）。補強不了的它會當場擋，並指名該走哪支工具。（2026-09-08 起）
5. **選擇器要指得到畫面上真的有的東西**（對位會把它翻成 ③ 找得回來的形狀）。翻不動的它會指名回報 —— 目前已知翻不動的只有**狀態偽類**（`:hover` / `:focus` / `:active` / `:visited`），那條還在想辦法；能用的清單見上面 §「② 你的自由」。
6. **整頁的字寫不進系統**：`body { font-size / color / background-color / line-height … }` 這種寫在 `body` / `html` / `*` 上的裸屬性，系統沒有「全站預設」這一層可以收，對位會擋下並指路 —— 請寫在具體元素上（`p`、`h1`、`.card`），效果一樣、③ 收得回。（2026-09-08 起）
7. **字級沒寫 `@media` = 三個裝置同一個值**：③ 會忠實照畫面寫回（那個字原本的桌機 / 平板 / 手機階梯會被壓平，只影響這頁）。想讓手機不一樣，就自己寫那一段 `@media`。（2026-09-08 起）
   ⚠️ **字級的斷點跟版面的不一樣，⛔ 別憑印象抄 `767px`** —— 查字典
   `domains.typography.breakpoints`（本站：平板 `max-width: 48.875em` ≒ ≤782px、
   手機 `max-width: 37.5em` ≒ ≤600px）。`1023px` / `767px` 是**版面**的界線
   （`domains['hf-sizing'].breakpoints`），拿它寫字級，中間那一段會對不上。
   寫成 `1023px` / `767px` 也會寫進去（③ 照寫不擋），但計畫書會多一段「📏 字級斷點落差」
   （理由碼 `typo_breakpoint_mismatch`）指名哪一段寬度仍是上一級的字級 —— 看到就回頭改成字典的斷點。（2026-09-09 起）
8. **block 與 block 之間的距離不是外距**：在 block 最外層（門牌就是整顆 block 那種）寫 `margin` 沒有用，系統把每顆 block 的上下外距釘死為 0；要拉開兩顆 block，寫那一段的 `padding`（③ 會收成 section 上下留白）。對位會擋下並指路。（2026-09-08 起）
9. **內距永遠只改這一頁**：你對某一種面的 class 寫 `padding`（例如 `.hz-surface-surface-05 { padding: 24px }`），③ 會展開成這頁掛那個 class 的每一張卡各自的內距，不會改到那種面的定義、不影響別頁。站主的定義：內距是每頁不同的東西。（2026-09-08 起）
10. **站主說 OK 的頁就凍結了**：那一頁之後**⛔ 不准自己回去改**。做後面的頁時發現「前面那頁應該跟這頁一致」，
    **只能提議**（記成一行，回報時列出來當 ③ 的題目），等站主說要改才動。
    站主原話：「沒有經過我同意不要主動去改已經修好的頁面，這是大忌。」（2026-09-09）
11. **custom HTML 是逃生口，不是工具箱**：用之前先讀 [seat-guide](../seat-guide/SKILL.md) §B-15（那裡是這條規矩的主人）。
    用了**記一行**（哪頁哪段、為什麼沒有合適的 block）—— 那一行就是日後轉成正式 block 的需求單，
    格式與落點見 [seat-guide](../seat-guide/SKILL.md) §B-15，用了請回報給站主。
    它現在不吃 token、③ 收不回，**這是已知的路**（產線之後會轉），⛔ 不必每次提醒站主。

## 「用 ③ 吃得下的方式寫」是什麼意思

只有兩件事：
- **寫在畫稿**（一段普通 CSS），跑對位送上草稿層 —— 不是寫進 HTML、不是用工具一格一格設。
- **值寫清楚**：hex 就 hex、長度就帶單位。不用轉成 `var()`、不用先查允許表、不用先吸附。

寫了 ③ 收不回的，**是系統的缺口，不是你的錯**（站主 2026-09-07 定調 A117）。回報時列出來就好，不要為了「收得回」改掉你原本的設計。

## 節奏

1. 看畫面、量現況（computed 值），寫下設計意圖。
2. 寫畫稿，跑一次對位送上去（上面「怎麼送」三步），抓前台看。不對就改那段再送。
3. 站主給回饋 → 回到 1。每輪動手前兩三句講要改什麼 + 貼 CSS 全文，做完再貼最終版。
4. 站主說「好了」→ 你**回報「這頁可以收了」，草稿層留著別清**。③ **不是你跑** —— 由 host
   或站主指定的操作手跑（規矩的主人是 [seat-setup](../seat-setup/SKILL.md) §6）；題目端過來時，你用白話答。
5. ⭐ **一個站的第一頁**：先畫**首頁**，拿它當**定調輪**收（你畫的值就成為新預設），再畫其他頁。

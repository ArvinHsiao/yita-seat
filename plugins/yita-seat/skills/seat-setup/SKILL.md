# 座位開始指南

> ⭐ **先讀 [seat-brief](../seat-brief/SKILL.md)**（座位總稿，站主 2026-09-07 定稿）。本頁任何一句與它衝突，**以它為準**，並回報那一句。
> **這頁只講「怎麼開始」** —— 環境、憑證、字典、開座位、誰跑哪一段。
> **怎麼畫**（每種元件能改什麼、值從哪選、寫在哪）全在座位手冊 [seat-guide](../seat-guide/SKILL.md)，這裡不重複。
> 座位**只碰 YITA Builder 的 MCP 工具**，不需要下載任何程式、不需要本機環境。

---

## 0. 每輪開工前：確認手冊是最新的

工具與規則幾乎每天都在改。用舊手冊畫，**每一步都照樣做得完、結果卻是照舊規則做的** —— 沒有任何錯誤訊息。

| 你怎麼讀手冊 | 開工前做什麼 |
|---|---|
| Claude Code 裝了 `yita-seat` plugin | 手冊隨 plugin 版本走；不確定是不是最新，就照 §2-1 重新安裝一次 |
| 其他工具用 GitHub 連接器讀 | 每次開工**重新讀** repo 裡的三本手冊，⛔ 不要沿用上次存下來的副本 |

## 1. 你要跑的是什麼

一頁網站分三段做，每一段走完停下來讓人看：

| 段 | 做什麼 | 誰做 |
|---|---|---|
| **① 形狀** | 用既有 block 把頁排出來（插 block、決定幾格、填站主給的文字） | **座位**（一個 AI session） |
| **② 感覺** | 在這一頁的樣式草稿層改長相（色、字、留白、動效），前台即時看得到 | **座位**（同一個，不換人） |
| **③ 收回** | 把畫對的長相翻成全站的 design token 寫回去，然後清掉草稿層 | **站主指定的操作手**（不是座位；見 §6） |

**你**（開發者）在中間：開座位、每一段走完看畫面、說留 / 換 / 好 / 不好、最後說 yes。

## 2. 第一次設定：接上 YITA Builder（做一次就好）

座位需要的只有**一條 MCP 連線**：`https://builder.hauzii.com/mcp`。**不用 key、不用設定檔** —— 第一次叫工具時會開瀏覽器，用 Google 帳號登入。

⚠️ 你的 Google 帳號要在該站的使用者名單內，登入才會通。登入後說「沒有權限」→ 請站主把你的帳號加進那個站。

### 2-1 Claude Code

**建議：裝手冊 plugin**（會一起帶上 `builder` / `builder-dev` 兩條連線與三本手冊）：

```
/plugin marketplace add https://github.com/ArvinHsiao/yita-seat
/plugin install yita-seat@yita-seat
```

**只要連線、不裝手冊**也可以：

```bash
claude mcp add --scope user --transport http builder https://builder.hauzii.com/mcp
```

⚠️ **不加任何 `--header`** —— 連線靠登入，不靠 key。
⚠️ **不加 `--scope user` 只在當下資料夾生效**。
⚠️ **兩條路擇一，不要都做** —— 已裝外掛又手動加一條同名 `builder`，手動那條會安靜蓋掉外掛那條。
⚠️ **裝之前先清掉同名的舊條目** —— 專案資料夾 `.mcp.json` 裡同名、帶 header（key）的條目，會安靜蓋掉你新裝的連線；user 層手動加過的同名條目也一樣。`disabledMcpjsonServers` 只管得到 `.mcp.json`，管不到 user 層。舊版外掛與舊教學用過的連線名（名字裡帶 `hauzii` 的那兩條）也一併清掉。
⚠️ **清掉舊條目後，先重開 Claude Code 再登入** —— 同一個 session 裡，已經移除的條目還會列在 `/mcp`，登入也會回「Authentication successful」，但實際登入的是舊條目。
⚠️ **裝完要重開 Claude Code** —— 工具清單是 session 啟動時載入的，不重開看不到新工具。

### 2-2 其他工具（Claude Desktop / ChatGPT / Codex …）

- **連線**：設定 → 連接器 → 自訂 → 網址填 `https://builder.hauzii.com/mcp`，一樣 Google 登入。
- **手冊**：用 GitHub 連接器讀這份 repo 的 `seat-brief.md` / `seat-setup.md` / `seat-guide.md`。

### 2-3 確認通了

叫一次 `site-get-info`（不帶參數）：

| 回什麼 | 意思 | 接下來 |
|---|---|---|
| 站名與網址 | 你的帳號只管一個站，之後都自動用它 | 開工 |
| 「站不明確」並列出好幾個站（`site_id` / 名稱 / 網址） | 你的帳號管好幾個站 | 開工先跟 AI 講要做哪個站；之後每支工具都帶那個站的 `site_id` |
| 要你登入 | 還沒登入或登入過期 | 照瀏覽器跳出的頁面用 Google 登入 |
| 回了站名，但沒跳出登入、也不是你要的站 | 還在吃舊的 key —— 同名舊條目帶著 key 蓋掉了新連線 | 照 §2-1 清掉同名舊條目 → 重開 Claude Code → 再登入 |

⚠️ **同一個帳號可以在好幾台電腦、好幾個視窗同時登入，不會互踢**（2026-09-15 起）。同一台電腦的多個視窗共用同一次登入；每台電腦要各自登入一次。
⚠️ **登入不會自動續期**（沒有 refresh token）：過期了就照瀏覽器跳出的頁面重新登入一次。這是設計如此，不是壞掉。

### 2-4 權限起手清單

**開工前請站主一次放行**下面這些工具，不要一支一支被擋在半路：

`site-get-info`／`design-get-dictionary`／`block-get-dictionary`／`page-clone`／`page-batch`／`page-get-structure`／
`design-update-style-layer`／`wp-rest`／`block-get-template`／`block-inspect`／`block-set-surface`／`block-set-style`／
`block-set-image`／`block-set-button`／`block-set-geometry`／`block-set-slot-visibility`／`block-set-repeater-visibility`／
`design-lint-style-layer`／`design-locate-style-layer`

權限設定裡要填**完整工具名**：`mcp__plugin_yita-seat_builder__` 加上工具名（例：`mcp__plugin_yita-seat_builder__site-get-info`）；要一次放行整條連線，就填 `mcp__plugin_yita-seat_builder`。

⚠️ 這是**起手清單**，不是權限表 —— 實際工具名以你那條 `builder` 連線列出來的為準。

## 3. 拿兩本字典（每輪開工前，用 MCP）

座位不該邊做邊查，開工前先把兩本字典讀進來。兩本都由雲端產、用 MCP 工具拿，不需要任何本機程式。


| 字典 | 是什麼 | 怎麼拿 |
|---|---|---|
| **token 字典**（樣式層字典） | 這個站每個「字」（`color.07`、`typo.03`…）的意思、變數名、現值 | `design-get-dictionary`：先不帶參數看目錄（`format:"index"`），再 `format:"md"` + `domain:"<章名>"` 逐章讀 |
| **block 字典** | 這個站裝了哪些 block、各適合放哪、有幾段文字幾張圖、能不能重複 | `block-get-dictionary`：不帶參數叫一次；在 Claude Code 會被存成檔案，照回應給的路徑用 `Read` 分段讀 |

```text
# token 字典（站台那一本）
design-get-dictionary {}
design-get-dictionary { "format": "md", "domain": "color" }   # 逐章

# block 字典
block-get-dictionary {}
```

- ⚠️ **token 字典一定要分章讀**：整份很大，超過單次回應上限會**被無聲截斷、不報錯** —— 你以為讀完了其實只看到一半。
- ⚠️ **block 字典一次讀不下**：在 Claude Code 呼叫 `block-get-dictionary`，結果太大（約 910 KB）會被存成檔案，回應只給存檔路徑 —— 照那個路徑用 `Read` 分段讀完，⛔ 不要只看回應裡的片段就開工。
- ⚠️ **版本**：需要站上 YITA plugin ≥ **2.6.4**；舊站會回 `404 unknown_endpoint` —— 請站主先更新 plugin。
- ⚠️ 不帶 `design_set` 拿到的是**站台 default 那本**。那頁若有自己一本 Design Set，要帶 `design_set: "<那本的 slug>"`；拿 default 去畫 page-set 那頁，值會是別本的。
  ⚠️ **目前沒有工具能回「某頁指派了哪本」** —— 問站主，或看 `design-list-sets`。
- ⚠️ **不必先抓前台讓樣式重生**：工具自己會重生；每次呼叫拿到的就是現在的值。
- ⚠️ 每輪 ③ 寫回之後，**重新呼叫一次**就拿到新值。
- 兩個座位同時讀字典**不用互相通知** —— 讀取不會覆蓋任何東西。
  （這跟 [seat-guide](../seat-guide/SKILL.md) §A-1 講的「兩個**通道**（草稿層 vs 工具）」是兩件事，別混。）

## 4. 開座位

**另開一個 session**，第一句話貼這段：

```
你是座位。先讀座位手冊 seat-guide（用 Read 工具讀檔，不要 cat），讀完等我聊專案。
排頁、畫、看結果都用 builder 這條連線的工具。
開工先拿兩本字典：design-get-dictionary（值，先 format:"index" 看章再逐章讀）、block-get-dictionary（block，存成檔案就用 Read 分段讀完）。
卡住就問我。
```


- ⚠️ **手冊與字典要用 `Read` 工具讀，⛔ 不要用 Bash `cat`** —— 手冊 40KB 出頭，`cat` 會超過 Bash 輸出上限被截斷，座位以為讀完了其實少一截，接著分好幾趟重讀（實測多花 4 趟）。這句話已經寫進上面那段開場詞裡了。
- **座位 ①② 是同一個 session**（它排的頁、它自己畫，中間不換人）。
- 座位**不 commit、不 deploy、不動 plugin**。
- 它會在每一段走完停下來給你前台網址，等你說話（四段定義在手冊 §0）。⭐ 它**聽不準會先問你**（「參考某頁」是要同一個形狀還是同樣的完成度、「擁擠」指哪一層…），那是刻意的 —— 回一句比讓它猜著畫一版便宜。

## 5. 跑起來之後你要做的事

> ⭐ **新站的起手式（B12 上線後）**：先畫**首頁** → 拿首頁跑 ③ 當**定調輪**
> （`--all overwrite`，你畫的值就成為新的預設）→ **再畫其他頁**。後面的頁大多會直接吸附到
> 剛定好的預設、題目自動變少。定調輪 vs 日常輪的規矩**主人在 §6 第 3 步**，這裡不重述。

1. **聊專案**：這頁要給誰看、要什麼感覺、有沒有現成文案與圖。
2. **回答開場那一題**：座位會問「這頁**沿用**站上的字典，還是**全部新開**一套？」—— 不確定就答沿用（預設）。這個答案 ③ 會用到。
3. **骨架**：看它列的段落清單（每段用途 + 候選 block）。點頭才讓它開始。
4. **① 形狀**：看前台的形狀。逐顆說**留**或**換**。
5. **② 感覺**：看長相。逐顆說**好**或**不好**。這裡還可以換 block。
6. **內容**：文案圖片補齊，跑到 `page-audit` PASS。
7. 你說 **yes** → 進 ③。

## 5-2. ② 的送法（**2026-09-07 起：寫畫稿 → 跑對位 → 看對位表**）

你在 ② 只寫**畫稿**：一段**普通 CSS**，指著畫面上看得到的東西，值寫你要的。
**你不用知道地址、門牌、token-class、兩層寫法** —— 對位會把選擇器翻成系統認得的形狀。

```text
# 1. 試跑（不帶 apply = 只回對位表，不真送）
design-locate-style-layer { page_id: <頁ID>, css: "<畫稿全文>" }

# 2. 看對位表沒問題 → 同一支加 apply: true 真的送上草稿層
design-locate-style-layer { page_id: <頁ID>, css: "<畫稿全文>", apply: true }

# 3. 看前台效果（網址加 ?x=<隨機數> 避開整頁快取）
```

工具會自己抓這頁的前台與字典，你不用先抓。


**對位表**逐條告訴你「你寫的 X → 我翻成 Y、命中 N 個元素」，還會說這條會不會一次動到好幾顆 block。
末尾有一段「③ 收回的預判」：哪些一定收得回、哪些是原始值要 ③ 逐條決定。

⭐ **表上這三欄要看**（2026-09-09 新增）：

| 欄 | 它在講什麼 | 你要拿它做什麼 |
|---|---|---|
| `same_kind` | 這一頁**同類**的元素總共幾個 vs 這條命中幾個（`{hits, total}`）| **這就是「命中誰 ≠ 全類都改到」的答案**（[seat-guide](../seat-guide/SKILL.md) §A-2）。`hits < total` 而你想改一整類 → 選擇器要放寬。命中的元素身上沒有語意 class 時是 `null`，不是 0 |
| `slot` | 這條實際落在哪一個 surface 槽 | 門牌形（`[data-hz-gap="…"]`）的 CSS 上看不出槽名，這欄會告訴你 —— 想確認「我改的是不是那個面」看它 |
| `warns` | 這條的警示（不擋，見 §5-3 末的 3 個警示碼）| 有值就看一眼，多半是 `target_retargeted` / `many_hits` |

⭐ **送出成功後把對位表留一份在你自己的筆記裡** —— 下一輪要回頭查「上一次我把什麼翻成了什麼」不用重跑，直接看它。


⚠️ 幾條要知道的：
- **`page-clone` 複製過來的頁，按鈕連結要逐顆對一遍**（2026-09-09）：顯示 / 隱藏（visibility）
  會跟著複製過來，但**按鈕的網址仍指著原本那頁的目的地**，看畫面看不出來 —— 要一顆一顆點或用
  `block-inspect` 對。⛔ 別假設「複製過來就都對了」。
  ⭐ 講清楚哪些**該**跟著走：slot / item 的 **visibility 一併帶走是對的、不用重設**
  （你在原頁藏掉的東西，新頁也是藏的）。**只有按鈕網址不跟新頁語意走** —— 它是「指向哪裡」，
  複製救不了，一定要人看過。
- **想知道某顆 block 的留白掛在哪一層**：`block-inspect` 的 `gap_carriers`，`element` 是掛載點、
  `as` 是軸。沒有 `as: 'pad'` 的載體 = 區段上下留白寫死、調不到（見 [seat-guide](../seat-guide/SKILL.md) §B-8）。
- **有任何一條對不到就整份不送**（不會送出一半）。失敗清單會指名第幾行、你寫的原文、為什麼。
- **你的畫稿原文會原樣留在草稿層頂端**（`hz-sketch:start … end` 那段註解），站主與下一輪看得到你的意圖；
  它是註解，對 ③ 零影響（原文的註解結尾會被轉義成 `*\/`，因為 CSS 不能巢狀註解）。
- 目前翻不動的只有**狀態偽類**（`:hover` / `:focus`），會指名回報。

### 5-3 它擋你的時候會說什麼（對位的 18 個失敗碼 + 3 個警示）

**任何一條被擋 = 整份不送。** 失敗清單會給你第幾行、你寫的原文、和下面這句話（回應裡每一筆 failure / warning 的 `label`）。
照「你該怎麼改」那欄改完再跑一次就好 —— **被擋不是你做錯**，是它在告訴你這條走哪一條路。

**沒送出去時先看 `not_applied_reason`**（回應 `applied: false` 一定會帶）：

| 值 | 意思 |
|---|---|
| `dry_run` | 你沒帶 `apply: true`，這次只是試跑 |
| `has_failures` | 下面這張表至少有一條擋下，整份沒送 |
| `draft_too_large` | 翻出來的草稿層超過上限（回應帶 `draft_max`），要拆短再送 |

| 碼 | 它會說 | 你該怎麼改 |
|---|---|---|
| `no_match` | 這一頁找不到你指的東西 | 選擇器指到的元素這頁沒有 —— 重抓前台（換 `?x=`）確認 class / 標籤，或把選擇器放寬一點 |
| `unaddressable` | 指到的東西沒有可以掛的位置 | 那個元素沒有系統認得的落點。改指到它外層有門牌 / 有 `data-hz-*` 的祖先 |
| `unsupported_selector` | 這種選擇器寫法還不支援 | 目前只有**狀態偽類**（`:hover` / `:focus` / `:active` / `:visited`）翻不動 —— 拿掉那一條，回報一聲 |
| `html_edit` | 這條指到頁面的機器（script / style），不是內容 | 你的選擇器掃到 `<script>` / `<style>` 了。加標籤或 `:not()` 限縮 |
| `important` | 不可以用 `!important` | 拿掉它。**該補強的機器會自己補**（見 [seat-guide](../seat-guide/SKILL.md) §A-2），你不用寫 |
| `changes_shape` | 這是改版面骨架，不是改長相 | `display` / `grid-*` / `flex-*` / `order` / `position` / `float` / `width` / `height` 這類要換 block，回 ①。（`max-width` / `min-width` **不算**，放行） |
| `parse_error` | CSS 這一行看不懂 | 那一行語法有問題（或用了不支援的寫法）。照它給的行號修 |
| `background_media` | 背景**圖**要用工具設，不寫草稿層（漸層可以直接畫） | `url(...)` 的背景圖歸 ①，用 `block-set-surface`。**漸層不受影響，照畫** |
| `gradient_unsupported` | 這個漸層 ③ 翻不回 block 資料 | 漸層寫得太複雜。改成單純的 `linear-gradient(角度, 色A, 色B)` 再試 |
| `gradient_no_slot` | 漸層只能落在 surface 槽上，這條沒有落點 | 把那條改指到 `[data-hz-surface="…"]`（③ 寫回要一個槽的地址）。訊息會告訴你原本指到的是什麼形狀。**門牌形（`[data-hz-gap="…"]`）已放行** —— ③ 會自動反查那顆載體身上的 surface 槽照寫，不用改寫成槽的地址。⚠️ 2026-09-09 起**只有反查不到才還會看到這個碼**：載體身上根本沒有 surface 槽，或同一個門牌對到好幾顆載體、槽名不一致（判不出來就不猜） |
| `block_root_margin_locked` | 外距寫在 block 根元素上會被系統蓋掉，畫面不會變 | block 與 block 之間的距離**不是外距**（系統把每顆 block 的上下外距釘死為 0）。改寫那一段的 `padding`，③ 會收成 section 上下留白（同 [seat-brief](../seat-brief/SKILL.md) 邊界第 8 條）|
| `root_bare_property` | 整頁只能改「字」的定義，不能直接寫屬性 | 你在 `:root` / `body` / `*` 上寫了裸屬性（`font-size` / `color` / `background-color`…），系統沒有「全站預設」這一層可以收。改寫在具體元素上（`p`、`h1`、`.card`），效果一樣、③ 收得回 |
| `pinned_inline` | 這個屬性被 block 釘在元素上（inline），草稿層蓋不過去 | 那個值是 block 自己的資料。⛔ 別寫 `!important`（會整份不送）—— 訊息會指名該走哪支 `block-set-*` 工具，走它 |
| `ancestry_inverted` | **兩種講法，看它給你哪一句**（見下方 ⚠️） | 見下方 ⚠️ |
| `heading_var_on_non_heading` | 這個變數只有標題（h1–h6）看得懂，你指的元素不是標題 | 你把 `--_hz-fs` / `--_hz-fw` / `--_hz-lh` 寫到 `<p>` / `<span>` 上了，那三個只有 heading 讀得到。⭐ **直接寫 `font-size` / `font-weight` / `line-height` 就好** —— heading 那邊對位會自己補（見 [seat-guide](../seat-guide/SKILL.md) §A-5 第 1 坑）|
| `door_not_covering` | 這顆 block 的門牌罩不到你指的地方，而這個地址別顆 block 也有 | 門牌只罩住這顆 block 的一部分，而你指的地址**全頁不只一個** —— 退成單層寫法會連別顆 block 的同名地址一起動，所以擋下。改指到**門牌底下**的元素，或換一個更內層、自己帶門牌的落點 |
| `ladder_undecided` | 你改了桌機字級，但沒說平板 / 手機要怎麼辦 | 那個字三個裝置本來不一樣，只寫桌機比例會跑掉。二選一（⛔ 不能都不寫）：①自己寫 `@media (max-width: 48.875em)`（平板）/ `(max-width: 37.5em)`（手機）那兩段；②畫稿最前面加一行 `/* hz-ladder: follow */`（整份都跟），或只在那一條加 `--hz-ladder: follow;` —— ③ 會照這格原本的比例推。見 [seat-guide](../seat-guide/SKILL.md) §A-5 第 2 坑 |
| `breakpoint_not_wp` | 這個 @media 寬度不是系統換字級的邊界 | 字級只在 `48.875em`（平板）/ `37.5em`（手機）這兩個邊界換值（≒ `782px` / `600px`）；寫別的寬度會有一段吃到桌機值、畫面上看不出來。訊息會列出本站那兩個值，照著改 |

⚠️⚠️ **`ancestry_inverted` 是同一個碼、兩句話，⛔ 別看到碼就以為是寫反了**：

| 它說 | 意思 | 你該怎麼改 |
|---|---|---|
| 「你指的東西和它的門牌**上下顛倒**了，這樣寫會選不到任何元素」 | 門牌是你指的元素的**後代** | 真的寫反了 —— 把兩者對調（門牌在前、你要改的在後）|
| 「**你沒寫反，是門牌罩不到**你指的地方」 | 門牌**不是**它的祖先（在同一顆 block 的另一支） | ⛔ **不要對調**（對調一樣選不到）。改指到真的罩得到它的祖先，或改用那個元素自己的 `data-hz-*` 地址 |

⚠️ 上面這個「罩不到」跟表裡的 `door_not_covering` **不一樣**：`ancestry_inverted` 是兩層寫法一個元素都選不到；`door_not_covering` 是門牌只罩住半顆 block、而且同一個地址別顆 block 也有。兩個的改法相同（改指到門牌底下、或換自己帶門牌的落點）。

**另外 3 個是警示，不擋、照樣送出**（送完記得看一眼，它們常常是「送出去了但不是你要的」）：

| 碼 | 它會說 | 看到要做什麼 |
|---|---|---|
| `target_retargeted` | 這條實際會動到的東西和你指的不一樣 | 對位把落點換到別的元素上了（多半是往祖先退）。看對位表的 `to` 是誰 —— 不是你要的就把選擇器寫精確一點 |
| `many_hits` | 這條命中的元素很多，草稿層會變很長 | 多半是後代選擇器碰上 repeater（格數 × 槽數，見 [seat-guide](../seat-guide/SKILL.md) §A-2）。確認你真的要全部一起改，不是的話加前綴限縮 |
| `door_not_covering` | 這條改用了單層寫法（門牌罩不到你指的地方） | 門牌罩不到，但這個地址**全頁就這一個**，所以改寫成單層、只會動到它自己。形狀跟其他條不一樣 —— 看一眼對位表確認動到的是你要的那顆 |

⚠️ **這張表的主人是對位工具的失敗碼定義**，不是這份手冊。實際訊息與這裡對不上時**以工具為準**，並回報一聲（表要跟著改）。

### 5-4 ③ 收回時才會看到的字（不是失敗，是申報）

下面這些**不會擋你**，是 ③ 產計畫書時列在「殘留」裡的理由 —— 意思是「這一筆畫面上看得到、但寫不回系統」。
殘留是產出的一部分，不是你做錯（見 [seat-guide](../seat-guide/SKILL.md) §B-14）。⛔ 別跟上面的失敗碼混在一起看。

| 理由碼 | 意思 |
|---|---|
| `pinned_inline_wins` | 這條被 block 自己的 inline 資料釘住，補強也蓋不過 → 該走 `block-set-*` 工具，計畫書會指名哪一支 |
| `slot_has_no_facet` | **「這個槽收不下這種樣式」**（2026-09-09 起語意收窄）：按鈕／徽章的槽身上沒有「字」這個欄位，所以**按鈕的字級、字距改不進去**。以前這種情形混在 `no_landing` 裡，而那個碼的意思是「系統裡沒有這個落點」，會害人去找一個根本不存在的機制缺口。⭐ **按鈕的字要整組換 → 改 button preset 的 `typo_preset`**（③ 目前不做這件事，已記臺帳）⇒ **這輪按鈕的字先不要在草稿層改字級／字距** |
| `typo_breakpoint_mismatch` | **不是殘留、有寫進去**，列在計畫書另一段「📏 字級斷點落差」：你 `@media` 寫的寬度 ≠ 字級實際生效的邊界（字典 `domains.typography.breakpoints`），它會指名哪一段寬度仍是上一級的字級。改成字典的斷點重送就消失（2026-09-09 起） |

## 6. ③ 收回怎麼跑（**2026-09-09 起：⛔ 不是座位跑**）

> ⭐ **這一段是「③ 誰跑」這條規矩的主人**（站主 2026-09-09 定調 D-3）。其他地方（[seat-brief](../seat-brief/SKILL.md)、
> [seat-guide](../seat-guide/SKILL.md) §0）只引用這裡，不重述。
>
> **③ 由 host 或站主指定的操作手跑，座位不跑。** 原因：③ 會寫**站級 token / 頁級 set**，
> 那正是同站其他座位畫稿當下所依據的值 —— 一個人跑 ③，別人畫到一半的頁就會在腳下變樣。
> 配套兩條：**同一站一次只跑一頁**；**跑之前先通知**（用 SendMessage 告訴 host 與 `ListAgents`
> 列得到的同站其他座位：「我要對 <站> 的 <頁> 跑 ③，接下來這段時間別畫、別重生字典」）。
>
> **座位這一步要做的只有三件事**：草稿層**留著別清** → 回報「這頁可以收了」→ 等操作手把題目端過來時
> 用白話回答站主看得懂的版本。⛔ 不要自己跑下面的指令。
>
> 2026-09-06 晚到 2026-09-09 之間手冊寫的是「座位自己跑」，**那句已作廢**。

## 7. 什麼要本機？

座位**全程只用 MCP 工具**，不需要任何本機程式。③ 收回由站主指定的操作手負責（見 §6）。


> ⭐ **要一張佔位圖但素材還沒到、上傳不了？**用
> `https://placehold.co/<寬>x<高>/<底色>/<文字色>.png` 直接當圖片網址，不必先上傳到媒體庫。
> **文字色寫成跟底色一模一樣**就會得到一塊乾淨的純色面（例如
> `https://placehold.co/1600x900/EDE7DA/EDE7DA.png`），⛔ 不會印出「1600x900」那行字。
> 這是暫時的繞法：正式素材還是要走 `site-upload-media` + `block-set-image`。

## 8. 卡住時先看這幾條

| 症狀 | 多半是 |
|---|---|
| 找不到 YITA Builder 的工具 | 沒重開 Claude Code（§2-1） |
| 叫工具時跳出要你登入 | 還沒登入、登入過期，或連線名改過（改名後要重新登入）（§2-3） |
| 回了站名，但不是你要的站、也沒跳登入 | 還在吃舊的 key：同名舊條目蓋掉了新連線（§2-1 清掉 → 重開 → 再登入） |
| playbook 說有某個參數，我的工具沒有 | 你的 session 比最近一次 builder 更新舊 → 重開 session |
| 改了草稿層前台沒變 | 整頁快取 → 網址加 `?x=<隨機數>` 再看 |
| 字典裡的值跟前台對不上 | 你手上那份是之前讀的 → 重新呼叫 `design-get-dictionary`（§3） |
| block 字典裡找不到某顆 block | 那顆沒同步到這站、或不是家族最新版（字典是**站級快照**） |
| 座位說「這個做不到」 | 先看手冊 §A-6：表上沒有的東西要**記下來回報**，不是硬做 |
| 還原草稿層之後變成**雙層標記** | 你把前台抓下來的整段**原樣**送回去了 —— 送回前要**剝掉首尾那兩行** `/* hz-style-layer:start … */` 與 `/* … :end */`（那是 plugin 自己包的，不是草稿層的內容） |
